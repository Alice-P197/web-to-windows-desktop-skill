# web-to-windows-desktop — 网页/HTML 一键打包为 Windows 桌面程序

## 技能概述

`web-to-windows-desktop` 是一个自动化技能，用户的输入只需是一个网页链接或一个本地 HTML 文件路径，即可在数分钟内生成两个可直接交付的 64 位 Windows 桌面程序产物：

- **便携版可执行程序** — 单个 `.exe` 文件，双击即可运行，无需安装，可放入 U 盘携带
- **NSIS 安装程序** — 标准 Windows 安装向导，支持自定义安装路径、桌面快捷方式、开始菜单和卸载

## 技术栈

| 组件 | 版本 | 用途 |
|------|------|------|
| Electron | 33.x | 提供 Chromium 内核 + Node.js 运行时，作为桌面应用的运行容器 |
| electron-builder | 25.x | 打包引擎，将 Electron 项目编译为 Windows 可执行程序 |
| NSIS | 3.x | Windows 安装程序生成器，创建标准安装向导 |
| Chromium | 130.x | 渲染网页内容的内核（随 Electron 附带） |

## 支持的输入方式

技能支持两种输入方式，会自动判断并采用对应的加载策略：

### 方式一：网页 URL

```
用户输入: "把 https://example.com 打包成桌面程序"
```

技能将 URL 直接写入 `main.js` 的 `mainWindow.loadURL(url)` 中。应用启动时即加载该网页，行为类似于一个独立浏览器窗口。

### 方式二：本地 HTML 文件

```
用户输入: "把 /home/user/my-app/index.html 打包成桌面程序"
```

技能会先验证文件是否存在，然后将该文件复制到项目目录中，在 `main.js` 中使用 `mainWindow.loadFile(path)` 加载。本地 HTML 的引用资源（CSS、JS、图片）会一并打包，实现完全离线运行。

## 可配置参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 目标 URL | 字符串 | — | 网页地址，需包含协议头 |
| 本地 HTML 路径 | 字符串 | — | 本地 HTML 文件绝对路径 |
| 应用名称 | 字符串 | 自动提取 | 窗口标题、快捷方式、安装目录名称 |
| 应用 ID | 字符串 | 自动生成 | 反向域名格式，如 `com.example.app` |
| 图标 | 文件路径 | 默认图标 | 256x256 的 PNG 或 ICO 文件 |
| 窗口宽度 | 数字 | 1280 | 默认窗口宽度（像素） |
| 窗口高度 | 数字 | 800 | 默认窗口高度（像素） |
| 最小宽度 | 数字 | 800 | 窗口最小宽度 |
| 最小高度 | 数字 | 600 | 窗口最小高度 |
| 单实例运行 | 布尔 | true | 是否只允许运行一个实例 |
| 输出目录 | 字符串 | `./dist` | 构建产物输出目录 |

## 两种产物的对比

| 特性 | 便携版 | 安装程序 |
|------|--------|----------|
| 文件名 | `AppName-portable.exe` | `AppName Setup 1.0.0.exe` |
| 安装过程 | 无需安装，双击即用 | 需运行安装向导 |
| 桌面快捷方式 | 手动创建 | 自动创建 |
| 开始菜单 | 无 | 自动创建 |
| 卸载 | 直接删除文件 | 控制面板或卸载快捷方式 |
| 注册表写入 | 不写入 | 写入安装信息 |
| 文件体积 | 约 80–120 MB | 约 80–120 MB |
| 适用场景 | 临时使用、U 盘携带、快速分发 | 正式分发、长期使用 |

## 安全设计

- 默认启用 `contextIsolation`（上下文隔离）和 `sandbox`（沙箱），限制渲染进程的系统访问权限
- 外部链接在系统默认浏览器中打开，不在 Electron 窗口内跳转，防止钓鱼
- 不在打包产物中嵌入任何密钥、令牌或敏感凭证
- 建议仅打包来自可信来源的网页内容

## 构建平台要求

| 构建平台 | 能否构建 Windows x64 产物 | 额外要求 |
|----------|--------------------------|----------|
| Windows 10/11 | 是 | 无 |
| macOS | 是 | 需安装 Wine |
| Linux | 是 | 需安装 Wine |

## 常见问题

### 产物体积为什么这么大

Electron 内嵌了完整的 Chromium 浏览器内核（约 80 MB）和 Node.js 运行时，因此最终产物体积通常在 80–120 MB。这是 Electron 架构的固有特性，无法显著减小。

### 构建失败怎么办

依次检查以下项目：Node.js 版本是否 ≥ 18；磁盘空间是否 ≥ 2 GB；网络是否正常（可尝试切换 npm 镜像）；是否在非 Windows 平台构建且未安装 Wine。

### 生成的应用能自动更新吗

可以。在项目中集成 `electron-updater` 即可实现自动更新，但这需要额外的服务器托管更新文件，属于进阶配置，不在本技能默认范围内。

### 本地 HTML 引用的资源会一起打包吗

会。`electron-builder.yml` 的 `files` 字段配置了 `assets/**/*` 和 `node_modules/**/*`，本地 HTML 及其引用的 CSS、JS、图片等资源均会打包进最终产物，实现完全离线运行。

## 与同类工具的关系

本技能在底层原理上与 nativefier 类似，但 nativefier 已于 2023 年 9 月宣布停止维护。本技能直接使用 Electron + electron-builder 的最新版本构建，避免依赖已废弃的第三方工具，同时提供更灵活的配置选项（本地文件支持、双产物输出等）。
